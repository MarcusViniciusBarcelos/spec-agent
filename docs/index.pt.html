Veja funcionar

O agente diz "done". O gate diz "ainda não".

Não é um prompt. É um checkpoint determinístico entre o seu agente finalizar e o código entrar.

o agente finaliza uma mudança │ ▼ gate do spec-agent ── lint · typecheck · testes · invariantes do projeto │ ┌────┴─────┐ passa falha │ │ ✓ entra erro volta pro agente ─→ o agente corrige ─→ o gate roda de novo
Invariante do seu projeto: cada espaço em branco → um traço
O diff final do agente — parece ok, entra errado
- const slug = name.trim().replace(/\s+/g, "-")  // "a  b" → "a-b"  ✗ colapsa repetições
gate do spec-agent (roda antes de o agente poder finalizar)
✗ FAILED — slug: whitespace invariant
↳ erro volta pro agente, finalização bloqueada
O agente roda de novo e corrige
+ const slug = name.trim().replace(/\s/g, "-")   // "a  b" → "a--b"  ✓
✓ gate passou — a mudança pode entrar

Sem o spec-agent, aquele primeiro diff entra. O agente achou que tinha terminado; o lint/typecheck/teste/invariante discordou — e o agente corrigiu antes de você ver o PR.

A tese

Agentes de IA são rápidos — e confiantemente errados.

spec-agent faz done significar: os testes passam, os contratos se sustentam, as regras do projeto são respeitadas e os erros recorrentes viram skills reaproveitáveis. É o contrato de qualidade entre seu repositório e seu agente de código — um tech lead automático que diz "Não. Isso não passa." Não é um prompt; é um checkpoint determinístico, medido com honestidade.

O que tem dentro

Poucas peças, cada uma para uma falha distinta

gate de verificação núcleo

Um Stop-hook determinístico que barra o "done" enquanto lint/typecheck/testes falham no que foi tocado. Pega o erro que o modelo não enxerga em si mesmo. O ROI mais claro.

project learning & skill-forge diferencial

Vira um erro recorrente do projeto numa regra imperativa e reaproveitável que o modelo de fato aplica — onde, sem ela, ele sabe a regra e a viola mesmo assim.

context-economy núcleo

Disciplina de tokens em prompt, tool input e resposta. Um grafo de código no lugar de reler arquivos.

agent-council avançado

Uma revisão multi-perspectiva reservada para decisões ambíguas de alto risco — migrações de DB, quebra de contrato, segurança, arquitetura. Não para o dia a dia.

skill-forge — aprendizado durável, na prática
// sem a regra aprendida — o modelo até cita a regra, e a quebra:
- const d = dto.expirationDate ?? dto.expiration_date  // fallback defensivo (viola a regra do projeto)

// com a skill no contexto:
+ const d = dto.expirationDate                        // corrige o tipo na origem, sem fallback

O que medimos

Um método reprodutível — e um primeiro sinal honesto

Um benchmark pequeno e tamper-isolated (o agente nunca vê os checkers). É um método mais um primeiro sinal, não prova — N pequeno, dito abertamente. Pra onde aponta:

achadosinal
O gate é o ganho concreto.Recuperou uma falha objetiva que o modelo entregou — tarefas-alvo foram de 80% → 100% via o fix-loop. Regras de prompt sozinhas moveram ~0 num modelo capaz.
Conhecimento durável muda o comportamento.Uma regra de projeto aprendida flipou uma resposta errada pra certa — o modelo sabia a regra e a violou sem a skill.
O nicho do council é calibração.Em tradeoffs ambíguos-mas-sãos ele nunca bloqueou à toa (0/4), onde um único pass bloqueou. Real, mas estreito — por isso "avançado".
Com um modelo base capaz, o diferencial aparece nas margens — no gate objetivo e no conhecimento durável do projeto, não em orquestração cara por padrão.

Método, números e ressalvas completos: RESULTS · SKILLFORGE · COUNCIL. N pequeno — indicativo, não prova estatística.

CI / pull requests

Faça "done" ser exigível, não um feeling

spec-agent verify roda o gate do seu projeto e imprime um veredito que lê como code review — verde no CI, bloqueando no PR, com exit não-zero quando bloqueia.

# .github/workflows/spec-agent.yml
- run: npx @marcusbarcelos/spec-agent verify
SPEC-AGENT VERDICT: BLOCKED

  ✗ domain contract  node --test
      idempotency invariant failed: duplicate ledger entry for sale-1

Blocked: 1 check(s) failed. Fix and re-run `spec-agent verify`.

Os checks vivem no .spec/manifest.yaml — seus testes, lint, typecheck, qualquer comando. É aqui que o spec-agent deixa de ser só assistente e vira o guardião do repositório. Demo rodável: examples/idempotency-demo.

Começar

Três comandos

# scaffolda .spec/ + adapters
npx @marcusbarcelos/spec-agent init --id meu-projeto --agents claude,agents-md

# re-projeta os adapters quando o engine evolui (não toca seu estado durável)
npx @marcusbarcelos/spec-agent sync

# roda o gate você mesmo (CI / PR) — veredito + exit não-zero se bloquear
npx @marcusbarcelos/spec-agent verify

Requer Node ≥ 20. O harness roda dentro do agente de código que você já usa.
