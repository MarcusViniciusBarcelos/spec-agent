See it work

The agent says "done." The gate says "not yet."

It's not a prompt. It's a deterministic checkpoint between your agent finishing and the code landing.

agent finishes a change │ ▼ spec-agent gate ── lint · typecheck · tests · project invariants │ ┌────┴─────┐ pass fail │ │ ✓ lands error handed back to the agent ─→ agent fixes ─→ gate re-runs
Your project invariant: each whitespace → one dash
The agent's final diff — looks fine, ships wrong
- const slug = name.trim().replace(/\s+/g, "-")  // "a  b" → "a-b"  ✗ collapses runs
spec-agent gate (runs before the agent is allowed to finish)
✗ FAILED — slug: whitespace invariant
↳ error handed back to the agent, finish blocked
The agent re-runs and corrects it
+ const slug = name.trim().replace(/\s/g, "-")   // "a  b" → "a--b"  ✓
✓ gate passed — change can land

Without spec-agent, that first diff ships. The agent thought it was done; the lint/typecheck/test/invariant check disagreed — and the agent fixed it before you ever saw the PR.

The thesis

Not another prompt framework.

When the base model is already capable, prompting alone barely moves the needle. The leverage is governance: block work that's objectively wrong, and teach the model your project's invariants so it applies them next time instead of re-deriving them wrong. spec-agent installs exactly that layer — and measures how much it pays.

What's inside

A few parts, each for a distinct failure

verification gate core

A deterministic Stop-hook that blocks "done" while lint/typecheck/tests fail on what was touched. Catches the error the model can't see in itself. The clearest ROI.

project learning & skill-forge differentiator

Turns a recurring project mistake into an imperative, reusable rule the model actually applies — where, without it, it knows the rule and breaks it anyway.

context-economy core

Token discipline in prompt, tool input, and output. A code graph instead of re-reading files.

agent-council advanced

A multi-perspective review reserved for high-risk, ambiguous calls — DB migrations, contract breaks, security, architecture. Not for everyday turns.

skill-forge — durable learning, in action
// without the learned rule — the model even cites it, then breaks it:
- const d = dto.expirationDate ?? dto.expiration_date  // defensive snake_case fallback (violates the project rule)

// with the skill in context:
+ const d = dto.expirationDate                        // fix the type at the source, no fallback

What we measured

A reproducible method — and a first, honest signal

A small, tamper-isolated benchmark (the agent never sees the checkers). It's a method plus a first signal, not proof — small N, stated openly. What it points to:

findingsignal
The gate is the concrete win.Recovered an objective failure the model shipped — targeted tasks went 80% → 100% via the fix-loop. Prompt rules alone moved ~0 on a capable model.
Durable knowledge changes behavior.A learned project rule flipped a wrong answer to right — the model knew the rule and violated it without the skill.
Council's niche is calibration.On ambiguous-but-sound trade-offs it never false-blocked (0/4), where a single pass did. Real, but narrow — hence "advanced."
With a capable base model, the differential shows at the margins — in the objective gate and durable project knowledge, not in expensive orchestration by default.
