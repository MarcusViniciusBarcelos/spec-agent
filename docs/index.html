Por quê

Não é mais um framework de prompt.

Quando o modelo base já é capaz, prompt sozinho move pouco. O que sobra de diferencial é governança: barrar o erro objetivo que o modelo não enxerga, e transformar erro recorrente do projeto em conhecimento que ele aplica da próxima vez. spec-agent instala exatamente essa camada — e mede o quanto ela rende, sem hype.

Os mecanismos

Cinco peças, cada uma para uma falha distinta

gate de verificação barato

Stop-hook determinístico que barra finalizar com lint/typecheck falho no que foi tocado. Pega o erro que o modelo não enxerga sozinho.

skill-forge barato

Vira erro recorrente do projeto em skill imperativa reutilizável. Conhecimento durável > memória que o modelo "sabe mas não aplica".

context-economy barato

Disciplina de tokens em prompt, tool input e resposta. Grafo de código no lugar de reler arquivos.

project-learning barato

Captura sinais de aprendizado em _pending/ e promove para learning/ do projeto.

agent-council seletivo

Painel multi-persona para decisão ambígua de alto risco. Calibra contra o falso-bloqueio — invocado só em planning/escalada.

thin + sync

O engine viaja no pacote; seu repo guarda só adapters + estado durável. sync nunca toca seu learning/ nem suas skills/.

O que medimos

Onde a governança rende — medido honestamente

gate

O mais barato e o de maior retorno. Quando uma mudança tropeça numa armadilha, o gate barra e o fix recupera — recuperação completa nas tarefas-alvo (80%→100%).

skill-forge

Conhecimento durável muda o comportamento. Uma regra do projeto vira skill imperativa e o agente passa a aplicá-la — onde, sem ela, conhece a regra e ainda assim a viola. Saber ≠ aplicar.

council

Calibra o que é ambíguo. Num painel de perspectivas independentes, a decisão de alto risco não é aprovada no susto nem bloqueada por excesso de zelo: zero falsos-bloqueios em tradeoffs legítimos.

Ground-truth tamper-isolated — o agente nunca vê os checkers. O diferencial está onde governança rende de verdade: barrar o erro objetivo e fixar o conhecimento do projeto.

Funciona com qualquer agente

Loss-model honesto, não promessa vazia

O harness completo roda no Claude Code; em outros agentes roda degradado-mas-funcional, com as perdas registradas no loss_report do manifest. Ninguém mais formaliza isso.

Enhancers específicos de um agente (claude-mem, superpowers, rtk, caveman) são opcionais — não dependências.

Começar

Dois comandos

# scaffolda .spec/ + adapters por agente
npx spec-agent init --id meu-projeto --agents claude,agents-md

# re-projeta adapters quando o engine evolui (não toca seu estado durável)
npx spec-agent sync

Pré-requisito: Node ≥ 20. O harness opera dentro do agente de código que você já usa.
